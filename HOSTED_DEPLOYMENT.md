# Hosted portfolio deployment: Render + Supabase

This is post-hackathon work. No live website is deployed yet.

The repository contains render.yaml for one Docker web service on Render's Free plan. Supabase stores projects, tasks, sessions and request limits; do not attach a local database to the free web service. Free Render services sleep after 15 minutes idle and can take about a minute to wake. This is a portfolio demo, not an availability guarantee.

## Deploy after PostgreSQL verification passes

1. Connect Render to GitHub and select Aizaz-Noor/Nova-Works. Use New > Blueprint and choose the tested portfolio branch.
2. Review the free plan before creating the service. Do not add paid databases or disks.
3. Enter DATABASE_URL privately using the Supabase Session Pooler URL. Never put it in GitHub or browser code. Set DATABASE_CA_CERT to the complete downloaded Supabase root certificate PEM text so certificate verification remains enabled.
4. Enter a rotated TOKENROUTER_API_KEY. Keep the model configured by render.yaml. SESSION_SECRET is generated by Render.
5. Set FRONTEND_ORIGIN to the exact HTTPS Render URL (no path or trailing slash). If the URL is not available until creation, update this setting before testing login.
6. Deploy, then check /api/health, login, transcript conversion, refresh, logout and manager/agent restrictions. Only call it deployed after the complete flow passes on the public URL.

Demo accounts are fictional and shared. Avoid private meeting data. AI calls are limited to 20 new extraction attempts per UTC day; failed calls also count. Identical saved transcripts reuse their result.
