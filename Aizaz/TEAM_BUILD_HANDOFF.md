## Shared API contract

All API paths begin /api; development frontend proxies /api to backend. Browser uses session cookie, never role/userId as authorization. Proposed local ports frontend5173/backend3001; record actual ports if unavailable. Demo runs built frontend served by Express on one origin when practical.

- POST /api/auth/login {email,password} -> {user}; wrong credentials401. Regenerate session on login.
- POST /api/auth/logout -> {ok:true}; destroy session.
- GET /api/auth/me -> {user}; no session401.
- GET /api/team -> {users:[{id,name,role,specialization,skills}]}; authenticated, no passwords/hashes.
- GET /api/projects -> {projects:[Project]}; authorized projects only.
- GET /api/projects/:id -> {project:Project,tasks:[Task]}; authorized tasks only; forbidden403 or404 consistently.
- GET /api/tasks/mine -> {tasks:[TaskWithProject]}; agents own tasks only.
- POST /api/transcripts -> {projects:[Project],projectCount,taskCount}; body {transcript}; admin only. Blank/invalid request400, unresolved/invalid draft422, provider failure502/504, unauthenticated401, nonadmin403.
- Error body {error:{code,message,issues:[{field,message}]}}; issues optional. No raw provider errors containing secrets.

Project: {id,name,clientName,description,managerId,managerName,deadline}. Task: {id,projectId,title,description,assigneeId,assigneeName,deadline,estimatedHours}. TaskWithProject adds projectName,clientName,managerName,projectDeadline. IDs serialized as strings; dates YYYY-MM-DD; hours finite positive numbers. Names come from seeded references, not new users generated by AI. UI ignores optional issues when absent.

AI draft uses official shape: projects[{name,clientName,description,managerId,deadline,tasks[{title,description,assigneeId,deadline,estimatedHours}]}]. Provider does not choose new record IDs or receive passwords. Admin sees all; manager projects where managerId matches session user; agent projects containing own tasks but receives only own tasks. All direct object requests enforce rules.

Three DB entities users/projects/tasks, foreign keys, unique email and password hashes. Idempotent seed ten users; generate project/task IDs in app; validate full draft before BEGIN/COMMIT; ROLLBACK on failure. Preserve separate projects and tasks even when same developer is shared. No fixed three/twelve output limit. Disable frontend repeated submit while processing. Sessions remain server-side; use suitable cookie settings for local/hosted environment. Actual API key/model/session secret remain private backend values. Only lead-authorized runtime resources; no account creation, deployment or unapproved paid calls.
