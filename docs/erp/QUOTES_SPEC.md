# Quotes and sales orders

Scope: company-scoped quotes connected to a customer and optionally a deal, with audited draft edits, immutable issued terms, recorded approval and replay-safe sales-order conversion. Internal records only; no email, customer portal, invoices or accounting entries.

OWNER/ADMIN/MANAGER read company sales records; managers mutate only their own records and must own the linked customer/deal. Only OWNER/ADMIN record customer acceptance/decline; they must supply an approval reference. MEMBER has no sales access. Acceptance records the authenticated internal actor; it does not claim independently verified customer identity.

Quote: title, customerId, optional dealId, currency USD/GBP/PKR, terms, validUntil (UTC calendar date), 1-50 items. Item: description, integer quantity1-1000000, unitMinor canonical integer string0-9007199254740991, taxRateBps integer0-10000. Server computes exact BigInt amounts; per-item tax rounds half up to a minor unit, totals sum rounded lines. No floats or client-supplied totals. Every line/header total must fit9007199254740991. Fractional quantities, discounts and jurisdiction tax automation deferred.

DRAFT can be edited with version; ISSUED terms/item/customer-name/email snapshot are immutable. POST issue locks the draft and records issue time. POST accept requires current issued version, nonexpired validUntil and approvalReference; ACCEPTED stores acceptedAt/acceptedBy/reference. POST decline requires reason. ISSUED/DECLINED may be revised: old quote becomes SUPERSEDED and one new DRAFT copies its terms; repeats return same revision. ACCEPTED cannot be revised/edited. A revision uses a new quote ID and supersedes_quote_id; never rewrites an approved document. API version is the optimistic mutation counter, distinct from revision ancestry.

POST /quotes/:id/order accepts {version}; ACCEPTED only, atomically copies exact approved header/items and quote_version to immutable sales_order/sales_order_items. Same quote retries return same order after current permission checks; concurrent requests cannot duplicate orders. It does not mark a deal Won, create an invoice or recognize revenue.

Endpoints /api/v1/quotes (GET paginated q/status, POST), /quotes/:id (GET,PATCH), /quotes/:id/{issue,accept,decline,revise,order} POST; /sales-orders GET paginated q, /sales-orders/:id GET. Mutations strict supported fields, NUL rejected, positive integer version. All authorized changes audit. IDs/company composite FKs. Migration006 additive, old checksums unchanged; four tables FORCE RLS; runtime quotes/items mutable only under business guards, orders SELECT/INSERT. Database triggers additionally reject changes to issued terms/items and any order UPDATE/DELETE. Dates do not imply delivery dates.

UI: Quotes tab with list/search/status/paging, customer search/paging, draft line editor, saved authoritative totals and snapshots; issue/revise/record approval/convert controls with clear consequences. Deal detail Prepare quote preselects linked customer/deal. Saved snapshots remain readable beside preserved conflict drafts. Sales orders have list/detail.
