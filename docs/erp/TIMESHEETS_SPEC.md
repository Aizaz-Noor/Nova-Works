# Timesheet slice

Flow: choose permitted company project/task -> save own dated time draft -> submit -> a different authorized reviewer approves or rejects -> scoped approved/billable minute summary. No billing rates, invoices, payroll, timers or revenue estimates in this slice.

Minutes are integer1-1440; actual workDate is a real YYYY-MM-DD date no later than current UTC day, billable is boolean, description required<=2000. Own-user daily total across non-VOID entries must not exceed1440. PostgreSQL mutations serialize against the worker membership row before checking totals; SQLite transactions serialize writes. No identity supplied by the client. Creation requires requestId<=100 nonemptytext, unique(org,user,requestId); identical retries return original entry after current read permission checks; changed payload409. Idempotency fingerprints preserve initial canonical input even after later edits.

OWNER/ADMIN may log own time on any company project/task. MANAGER may log on managed projects, or a task assigned to themselves elsewhere. MEMBER must choose a task currently assigned to themselves. Task/project company composite FK enforces relationship. Own historical records remain readable. Draft edits/submission recheck current project/task permissions; VOID is allowed for own draft/rejected entries to discard a mistake.

States DRAFT/REJECTED editable by worker only -> SUBMITTED (submission number increments) -> APPROVED or REJECTED. SUBMITTED content is frozen; APPROVED/VOID terminal and immutable. No selfapproval, including owners/admins. OWNER/ADMIN review another worker's submitted entry; MANAGER only for projects they manage. Rejection requires note; approval note optional. Approvalhistory append-only with submitted version/submission number/reviewer/decision/note/time, unique per submission. Review conflicts yield409; no silent repeated approval. No reopen of approved entries; accounting corrections/billed linkage deferred, so approved minutes cannot currently become invoiced.

GET /api/v1/time-entries supports scope=mine(default)|team, status,from,to,projectId,q,page,limit<=100. Team is management-only, excludes private DRAFT/VOID; managers see only their projects. Details/history: self, or reviewer for nonprivate records. Response entries,pagination,summary string minutes/billableMinutes/approvedMinutes/approvedBillableMinutes aggregated over the whole authorized filtered result, not just page. All summary metadata must respect the same scope. GET /time-projects paged/q and /time-projects/:id/tasks paged/q expose only selectable records; unauthorized project404. GET /time-entries/:id returns entry plus approvals. POST create {requestId,projectId,taskId?,workDate,minutes,billable,description}; PATCH edits {version,...fields} excluding identity/requestkey; POST /:id/{submit,void} {version}; POST /:id/review {version,decision:APPROVE|REJECT,note?}. All mutations strict fields/NUL/type checks and audit; current positive version required. Replay creation has no new audit.

Database triggers protect immutableidentity,version/state transitions,submittedcontent and approved/void rows; approvals cannot UPDATE/DELETE. One private runtime credential still requires API membership/role authorization.
