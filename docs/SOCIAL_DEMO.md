## Recording and editing

One practical capture option is **OBS Studio**: select the browser window as the capture source, verify the microphone meter, and make a short test recording before the full take. These steps are supported by the official [OBS Quick Start Guide](https://obsproject.com/kb/quick-start-guide), checked 8 October 2026. This is a recommendation, not a claim that OBS is installed or a recording was made with it.

For an editor, **Shotcut** supports subtitles and video export. Its official [feature list](https://shotcut.org/features/) documents subtitle import/edit/export, and the official [Subtitles panel guide](https://forum.shotcut.org/pub/subtitles-panel) explains separate SRT export. Check the controls in the installed version. Do not install another editor if the team already has a working one.

Recommended editing sequence:

1. Keep the raw take unchanged. In a separate edit, trim dead space before/after actions; preserve cause → response → saved output.
2. If shortening a genuine provider wait, retain a moment of the actual processing state, then display **“Processing wait shortened”** across the cut. Do not print an invented duration or imply instant generation. Use “Navigation pauses shortened” if that is what was trimmed. A saved replay must still be labeled a replay, even if it briefly shows a busy state.
3. Record or clean a calm voiceover. Avoid background music under essential narration; if used, keep it quiet and use material with suitable rights. No decorative zoom should hide error/replay wording or make a different result appear.
4. Add synchronized subtitles for every spoken sentence. Correct names, dates, role labels and technical terms manually. Use one or two short lines, readable high-contrast text and a solid or sufficiently opaque backdrop. Keep captions away from task owners, deadlines, controls and platform overlays. Do not convey an important distinction by color alone.
5. Keep short information captions separate from verbatim subtitles: “Saved sample reused” is disclosure, not a replacement for the narration's caption track. Provide an SRT file and/or uploadable caption track alongside the video; a burned-in caption copy is useful when sharing muted autoplay clips.
6. Export a practical master as MP4 with H.264 video, AAC audio, 1920×1080, 30 fps; these are suggested output settings, not a claim about platform limits. Export a vertical adaptation at 1080×1920 only after reframing readable sections. Do not squeeze a full desktop screen into portrait. Keep essential content comfortably inside the edges and inspect the actual destination preview.
7. Play the exported file from beginning to end, with sound and once muted. Check text readability, subtitle timing, correct account identities, actual counts, disclosure labels and URLs. Keep an accessible written summary in the post description for users who cannot use the video.

A small deliverable set: landscape master MP4, vertical adaptation if useful, subtitles.srt, thumbnail, raw uncut capture and a text description containing release/date and footage disclosures. Prepare files locally; publishing requires the lead's instruction.
